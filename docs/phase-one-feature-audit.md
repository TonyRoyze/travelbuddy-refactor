## What was ported in this pass

- Legacy search suggestions and date/duration controls, plus the missing Live Now search switch, using the existing Supabase API boundary rather than Next.js/Prisma runtime imports.
- Full experience photo viewer, including all saved photos, keyboard navigation and accessible dialog controls.
- Inventory-aware filtering before ordering/pagination. It considers every pricing option, skips full/closed dates and excludes expired/offline providers from Live Now.
- Reliable URL booleans and filter reset/preservation. The home page still requests Sri Lankan packages only.

## Verification

Core checks: `pnpm typecheck`, `pnpm lint`, `pnpm test`, `pnpm build`, `pnpm test:db` and `pnpm test:compat`. Database tests use the disposable `travelbuddy_refactor_test` database and roll back fixtures.

Local end-to-end checks (Vite/media service and the local Supabase Docker stack must be running):

```sh
pnpm test:nearby:http --keep-fixtures
# Use the private fixture path printed by the preceding command:
pnpm exec tsx scripts/test-phase-one-http.ts /generated/fixture.json
pnpm exec tsx scripts/test-profiles-http.ts /generated/fixture.json
/path/to/playwright/python scripts/test-phase-one-browser.py /generated/fixture.json
/path/to/playwright/python scripts/test-nearby-browser.py /generated/fixture.json
pnpm test:nearby:http --cleanup /generated/fixture.json
```

HTTP checks exercise real self-registration, onboarding, persisted profiles, chat without reservations, online/offline search, multiple bookings, exact retry replay, private history and cancellation. Browser checks use real forms for registration, onboarding, photo/bio editing, search and gallery, provider online/offline controls, chat/reply/selection return, persistent cart/edit, multi-item checkout, confirmation, booking history/cancellation and mobile filters. The separate Nearby browser suite verifies pins, map/list switching, location editing and app-close expiry.

The browser registration test assumes the local Auth stack’s email auto-confirm setting. A deployment requiring email verification must complete its confirmation flow. The browser scripts use Python Playwright; set `PLAYWRIGHT_CHROMIUM_EXECUTABLE` to your installed Chromium path if needed. Test credentials remain in a private temporary file. Cleanup verifies fixture identities and removes only their test reservations, accounts, packages, conversations and uploaded media.

Live discovery uses bounded polling and expiring presence, not WebSocket push. Cart persistence is per browser/account, not cross-device synchronization. Neither version supplies online payment processing. Unrelated legacy saved items, reviews, public requests and support pages are outside this requested Done-feature audit.
